# 定制自己的规则

原则：**规则和风险偏好由用户定**，Agent 负责把它写清楚、找出漏洞、用历史数据检验。
我们不提供「该买该卖」的结论。

## 1. 问清三件事（一次问完，别反复追问）

- 目标与期限：比如 3~5 年稳健增值、能接受的最大回撤是多少。
- 标的范围：只做宽基 ETF？哪几个指数？
- 想法来源：自己的判断、某篇文章、某个指标。

## 2. 写成规格表

| 字段 | 示例 |
|---|---|
| 指标 | 沪深300 相对长期中枢偏离 / 恐慌指数 |
| 触发条件 | 偏离 < 0 且恐慌 ≥ 75 |
| 执行时点 | 收盘后判定、次日开盘执行 |
| 仓位规则 | 每次投入现金的 20%，单指数上限 40% |
| 退出 | 有 / 无；条件写清楚 |
| 风险上限 | 总回撤超过 X% 停止加仓 |

**必须有退出腿或明确写「不退出」**——很多想法只想好了买，没想好卖。

## 3. 用历史数据检验

1. 取数：`fear_series`（2005 起）、`bias_series`（近一年）、`macro_series`；指数价格请用户用自己的数据源（我们不转售原始行情）。
2. 在本地写 Python 回测，参数放顶部；跟「同样现金流的定投 / 买入持有」对比，不要只看绝对收益。
3. 必报四项：年化、最大回撤、触发次数、触发日期清单。触发次数太少（如十年不足 8 次）要直说结论不可靠。
4. 前后半段分开看，两段方向不一致就是不稳。

## 4. 如实写结论

- 规则跑输基准、样本太少、只在某一段有效，都要直接写出来。
- 引用 `methodology_get` 里的「历史验证」结论作对照：比如乖离率作信号已被多种口径否定，用户想用它就要先说明这一点。

> 所有内容仅供研究参考，不构成投资建议；实际操作由用户自行决定并承担风险。

## 点数与报错

工具返回「Journey 点数不足」时：停止后续调用，把报错里的剩余点数、充值链接和价格原样告诉用户，说明充值到账后直接重试即可（Key 不用换）。不要反复重试，也不要换别的工具绕过。

工具结果末尾出现「【Journey 提示】」（点数快用完）时，在回答末尾原样转告用户一次，之后不要重复。

调用报 API Key 相关错误（没读到 Key、格式不对、不存在、已吊销）时，按 `getting-started` 里的排查表把修法告诉用户，不要反复重试。
